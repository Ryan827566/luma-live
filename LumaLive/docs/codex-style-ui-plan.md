# LumaLive：Codex 风格桌面 UI 改版评估

更新：2026-10-14。最初基线：main `053cabd6`；首阶段提交 `9954f15b`。用户已授权评估后立即实施。

## 目标与边界

将登录、账户管理和登录后的主工作区统一为 Codex 客户端风格：安静的中性色背景、最左侧导航、明确的内容层级、克制的边框与圆角、集中而易读的表单。保留 LumaLive 名称和专属图标。

现有 Win32/C++ 原生客户端继续使用；本轮不迁移到 Electron/WebView，不改认证协议或存储格式。按照用户 2026-10-14 最新要求，启动只显示登录/注册入口，取得有效登录会话后显示功能工作区及当前账户信息；注册成功本身不解锁。正常切页保留通话/会议/AI 会话，退出或会话失效则停止媒体和当前客户端拥有的 AI 服务并返回入口。不会自动开启摄像头或麦克风。

## 参考依据

- 本机已安装 `OpenAI.Codex_26.928.3736.0` 的只读样式资源：`app-primary-547a6c7b4fb3.css` 和 `app-shared-342447930c78.css`。读取到深色基础 surface `#212121`、secondary `#303030`、text `#ffffff`、secondary text `#cdcdcd`，以及独立的侧栏/主表面、控件圆角变量。不同主题可覆盖这些值；这些是资源证据，不是当前窗口的像素测量。
- [OpenAI 官方 Codex app 介绍](https://openai.com/index/introducing-the-codex-app/)支持工作区与任务上下文保持的产品方向。本次未取得可验证的当前登录页截图，不声称逐像素复刻。
- `frontend-design` 指导用于颜色、字体、间距、状态和交互一致性。最新 Codex 风格要求优先于历史 Figma 蓝黑配色方向。

下述尺寸、布局和组件映射是为 LumaLive 制定的设计决策，不是 Codex 官方设计规范。

## 设计契约

| 项目 | 实施约定 |
|---|---|
| 配色 | 主背景 #212121；侧栏 #181818；输入面 #282828；悬停/选中 #303030；正文 #f3f3f3；次要文字 #b4b4b4；边界 #424242。蓝色保留给焦点和媒体状态；主提交用浅色底、深色字。 |
| 字体 | Windows 原生 Segoe UI / Microsoft YaHei UI；正文 14 DIP、辅助 12 DIP、页面标题 24–26 DIP；不引入字体下载依赖。 |
| 间距 | 4/8/12/16/24/32 DIP；导航行 36–40 DIP；表单标签与字段间 8 DIP；标题和正文有清晰间隔。 |
| 左导航 | 顶部品牌，视频通话/视频会议/AI 助手为普通图标文字行，当前项柔和填充；账户入口固定底部。紧凑窗口收窄，避免挤掉视频操作。 |
| 未登录 | 内容区居中单列表单，登录/注册/找回/连接仍在页内切换；主操作紧接字段，状态紧接主操作；说明文字弱化，不用空的大信息面板。 |

| 交互 | 原生编辑、文本选择、IME、Tab/Shift+Tab、Enter/Escape、可访问名称保留；动效遵循系统设置。错误/加载/空状态在页面内呈现。 |

## 工作量与周期

估算为有效开发、构建、检查时间，不包含额度等待、睡眠或外部设备准备；不是保证的自然日交付时间。基于现有代码审计：共享主题已有，主窗口和会议仍有重复颜色与几何；不需要重做已验收的账户协议。总计 **24–40 小时，约 3–5 个 8 小时工作日**。若每天只能完成约 4 小时有效开发，则约 6–10 天。每阶段以可运行 EXE 和提交验收。

| 阶段 | 交付物 | 预计工时 | 起始状态 |
|---|---|---:|---|
| 1. 登录与框架 | 中性灰主题、侧栏层级、居中登录/注册/找回、关键回归及截图 | 6–10 小时 | 开始实施 |
| 2. 已登录账户 | 资料/安全/设备/连接布局、细化错误/加载/确认与键盘路径 | 4–6 小时 | 待做 |
| 3. 通话与会议 | 页面层级、视频与控制区、紧凑尺寸、状态和控件一致性 | 6–10 小时 | 待做 |
| 4. AI 工作区 | 会话/历史/服务设置完整视觉统一，长文本和状态布局 | 4–7 小时 | 待做 |
| 5. 全面回归 | 简繁英、96/144/192 DPI、紧凑/常规截图、导航与功能回归、修复 | 4–7 小时 | 待做 |

物理多屏、真实 IME/Narrator、高对比度需实际环境验收，另预留 0.5–1 天执行；未完成时单列，不能用模拟消息代替。真实邮件/SMS、认证 TLS、数据库部署、真实 AI/双机媒体及尚缺 AI 功能属于功能开发，**不包含在本 UI 工期中**。

## 验收与用户测试

1. 运行 `D:\workspace\luma-live\output\next\Release\luma_studio.exe`，首先应只看到登录入口；测试注册、找回和连接页，错误文字、显示密码与切页遮蔽。没有可连接的账户服务器时，应停留入口并显示错误，不提供绕过登录的生产开关。
2. 登录本地测试账户后看资料/安全/设备/连接；切通话、会议、AI 再返回，确认状态保留。不要在生产账户上测试删除。
3. 自动验收用 `C:/Python314/python.exe scripts/windows/verify_client.py`：实际 EXE 构建、账户/AI/导航工作流、原生单元检查及独立会议渲染诊断共 24 项。账户流程使用独立内存服务和测试投递器，不碰用户数据库。诊断会议程序与正式客户端入口分离。
4. 检查简体/繁体/英文、1024×700 和常规尺寸、96/144/192 DPI；截图记录目录及 EXE SHA256。
5. 功能断言不能为迁就新 UI 而删除；尺寸断言按新契约调整且解释原因。每阶段直接提交 main。
