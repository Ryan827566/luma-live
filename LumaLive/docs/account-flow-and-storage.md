# 账户模块：注册流程、数据保存与部署状态

更新：2026-10-14。依据本仓库账户客户端、账户服务器和存储实现核对；未读取数据库连接串、密钥、用户数据库或进程命令行。

## 先回答两个问题

**账户服务器已经有实现，也有已编译的程序；这不等于已经部署为可供正式用户使用的线上服务。** 当前包含注册、密码/短信登录、资料、验证、双重验证、密码重置、设备会话与安全活动接口，以及 PostgreSQL 存储适配器。

**注册资料由连接的账户服务器保存，不写在客户端的连接配置文件里。** 保存到哪里取决于服务器使用的存储实现。特别需要区分：底层库允许内存存储，但正式 `luma_auth_server.exe` 入口强制要求 PostgreSQL 配置，不会在缺少数据库时悄悄使用内存。

登录门禁已实现并通过本机真实客户端验证：注册后仍需登录，左栏显示名称和邮箱，退出或后台验证失败返回入口。会话每60秒检查一次，正在执行的账户操作完成后再检查，因此远端撤销不是瞬间检测。此界面门禁不代替服务端权限校验或尚未接入的TLS。

## 数据流与职责

```text
客户端账户表单
  → AccountService：连接账户服务、执行注册/登录协议
  → AuthServiceImpl：字段校验、挑战、身份验证、会话与权限检查
  → IAuthStore
      ├─ PostgreSQL：正式服务器入口要求配置
      └─ 内存实现：显式测试/库调用，进程退出后资料丢失
```

| 层级 | 实现位置 | 具体职责 | 不代表什么 |
|---|---|---|---|
| 账户界面 | `client/ui/studio-preview/src/AccountPanel.cpp` | 收集表单、显示加载/错误、发起后台操作、展示资料与安全状态 | 页面显示出来不代表服务已运行 |
| 客户端账户服务 | `client/account/src/AccountService.cpp` | 连接服务器，注册、登录、刷新会话、管理账户 | 不维护客户端用户数据库 |
| 账户服务器 | `server/auth/src/AuthServiceImpl.cpp` | 验证挑战与凭据，处理账户操作、会话、验证码与审计 | 实现存在不代表已部署到公网 |
| 存储适配器 | `server/auth/src/AuthStore.cpp` | 内存或 PostgreSQL 的用户/安全活动读写 | PostgreSQL 适配器通过编译不等于实际数据库部署验收 |
| 服务器程序 | `apps/luma-auth-server/src/main.cpp` | 检查配置、启动服务、等待停止 | 当前仍是命令行进程，尚未证明生产服务托管、备份和恢复完成 |

## 注册资料究竟保存在哪里

| 运行方式 | 选择条件 | 保存位置 | 进程重启后的结果 |
|---|---|---|---|
| 正式 `luma_auth_server.exe` | 必须提供 `LUMALIVE_AUTH_DATABASE_URL`，并完成数据库连接 | 连接串指定的 PostgreSQL 实例和数据库 | 成功写入的用户与安全活动应保留；实际跨进程持久化仍需部署验收 |
| 单独调用默认存储工厂 | 环境中没有数据库连接配置时，库工厂返回内存存储 | 该服务器进程中的对象/容器 | 整个进程退出后丢失，不是本地文件持久化 |
| 测试专用账户服务 | `AccountUiFixture` 显式注入内存存储和捕获式邮件/短信提供器 | 隔离测试进程内存 | 测试结束即不再保留，不触碰用户数据库 |
| 客户端连接设置 | 用户显式连接成功后保存 | `%LOCALAPPDATA%\LumaLive\account-connection.conf` | 保留服务器 IPv4 地址与端口；不包含注册资料、密码或令牌 |

PostgreSQL 的物理数据目录由数据库服务器部署决定，不能从 LumaLive 客户端安装目录推断。数据库可能在本机，也可能在远端；本文未检查实际连接配置，因此不声称用户资料已经落到某台数据库服务器。

内存存储的 `Close()` 仅关闭访问状态，同一个存储对象重新打开可能仍能看到原数据；这不能作为“进程退出后仍持久保存”的证据。

## 数据表与敏感信息处理

当前建表代码和 `server/auth/db/schema.sql` 中只有以下两张账户相关表；没有已实现的持久化会话表或短信挑战表。

| 数据 | PostgreSQL 表/位置 | 当前保存内容与方式 |
|---|---|---|
| 用户身份与资料 | `luma_auth_users` | 用户 ID、用户名、邮箱、显示名称、头像地址、手机号；头像字段是地址，不是头像文件本身 |
| 密码验证信息 | `luma_auth_users` | `password_salt`、`password_verifier`、`password_kdf_iterations`；不保存原始密码和确认密码 |
| 验证状态 | `luma_auth_users` | 邮箱、手机、双重验证是否启用 |
| 邮箱验证与密码重置 | `luma_auth_users` | 验证/重置令牌的哈希和过期时间，不是原始令牌 |
| 双重验证 | `luma_auth_users` | 恢复码哈希、TOTP 密钥 `mfa_totp_secret_hex`；此密钥目前是十六进制编码，不能称为已加密存储 |
| 安全活动 | `luma_auth_security_events` | 事件 ID、用户 ID、类型、详情、时间；用户表有用户名/邮箱大小写不敏感唯一索引和非空手机号唯一索引 |
| 登录会话和设备列表 | 服务器内存 `sessions_` | 访问令牌作为映射键，刷新令牌保存哈希，以及设备、用户、过期时间；即使启用 PostgreSQL，这部分目前也不持久化 |
| 短信验证码挑战 | 服务器内存 `phone_challenges_` | 手机号、用途、用户、挑战与验证码组合的哈希、过期时间、剩余次数；进程重启后失效 |
| 登录后客户端状态 | 客户端进程内存 | 当前资料、访问令牌和刷新令牌；当前没有“记住登录”的凭据落盘功能 |

## 注册、登录和验证码流程

| 操作 | 实际流程 | 当前边界 |
|---|---|---|
| 注册 | 发送用户名/邮箱/显示名称；服务器发回随机盐、随机挑战和迭代参数；客户端用 PBKDF2-HMAC-SHA256 派生验证值；服务器写入用户后返回成功 | 当前配置为 600,000 次迭代。注册成功后回到登录，不等于已验证邮箱或已发送真实邮件 |
| 密码登录 | 服务器提供盐和随机挑战；客户端重新派生验证值，再生成 HMAC 挑战证明；服务器校验后签发会话 | 客户端限制挑战参数，拒绝畸形或过大迭代挑战；挑战证明不能代替 TLS 加密传输 |
| 会话刷新 | 访问令牌配合刷新令牌；成功后轮换访问和刷新令牌 | 访问有效期按代码为 24 小时，刷新为 30 天；服务器进程重启仍会丢失当前内存会话 |
| 邮箱验证 | 生成随机令牌，通过邮件提供器发送；保存哈希与 30 分钟期限；成功验证后消费挑战 | 当前没有已实现的真实生产邮件提供器 |
| 手机验证/短信登录 | 挑战绑定手机号及用途，验证码哈希在服务器保存；期限 5 分钟，挑战最多 5 次尝试 | 生产短信提供器未实现；测试模拟投递不能作为真实短信验收 |
| 修改密码/找回密码 | 更新验证值；成功后撤销该用户会话；重置令牌按哈希验证并一次性消费 | 找回邮件令牌期限为 30 分钟；真实邮件与跨进程数据库部署验收仍需完成 |
| 退出登录/设备撤销 | 撤销相关会话，客户端清理身份状态；危险操作通过页内确认 | “已退出当前客户端”和“持久化多实例会话撤销”不是同一能力，后者尚未完整交付 |

密码未以明文保存，不意味着当前认证链路已经达到生产要求。注册会传输密码派生验证值，登录响应包含会话令牌；当前是自定义 TCP 协议，尚未接入认证 TLS，不能把挑战协议描述成安全的加密通道。

## 服务器如何启动，目前能确认到哪一步

| 项目 | 代码或本次检查能确认的事实 |
|---|---|
| 程序存在 | 本次确认 `output/next/Release/luma_auth_server.exe` 文件存在 |
| 启动参数 | `luma_auth_server [port]`，默认端口 9100；当前服务绑定所有 IPv4 网卡地址 |
| 运行环境 | 入口要求 `LUMALIVE_AUTH_ENV`；开发/测试允许模拟提供器 |
| 数据库 | 入口强制要求 `LUMALIVE_AUTH_DATABASE_URL`；通过 libpq 连接指定数据库，初始化所需表/索引；不是创建一个新数据库服务器 |
| 生产投递 | 非开发/测试模式要求真实邮件与短信提供器，但当前其它提供器名称均返回“未实现/未配置”；仅填写名称不能使生产服务可用 |
| 运行状态快照 | 2026-10-14 此次只按进程名称检查，未发现 `luma_auth_server`、`luma-auth-server` 或 `luma_account_ui_fixture`；这只是本机当时快照，不能推断远端部署状态 |
| 检查范围 | 未读取环境变量值、数据库内容、密钥或进程命令行，未连接用户数据库，未启动或停止账户服务 |

测试提供器分两类：开发提供器会返回专门的调试验证码字段，不实际发送邮件/短信；UI 自动验收使用注入的捕获式提供器，仅通过测试私有管道取合成验证码。两者都不能作为面向真实用户的消息投递服务。

## 已完成与下一步

| 项目 | 当前状态 | 下一步验收 |
|---|---|---|
| 账户服务协议、客户端和页面 | 已实现；已有隔离账户流程回归 | 登录门禁接入后重跑注册→登录→进入工作区→退出流程 |
| PostgreSQL 适配器和表结构 | 已实现 | 用专用验收数据库验证服务跨进程重启、更新/删除、失败处理；不使用用户数据库做破坏性测试 |
| 登录后才能进入工作区 | 本机验收通过 | 未登录无法进入模块；成功登录可进入；退出/失效后的行为可验证 |
| 真实邮件与短信 | 未实现生产适配器 | 配置真实服务并验证送达、失败、频控与验证码不泄露 |
| 认证加密传输 | 未完成 | TLS、证书与服务器身份验证及错误处理 |
| 持久会话/记住登录 | 未完成 | 单独设计安全存储、重启恢复、轮换与撤销，不把保存服务器地址当成保存登录状态 |
| 正式部署 | 未证明已完成 | 数据库部署、服务托管、访问控制、备份恢复、生产投递和加密传输逐项验收 |
